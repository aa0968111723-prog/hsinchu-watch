# WebGL 評估｜政策與工程地圖

結論：**首批與目前擴充不採用 WebGL**。平面與立體示意都以 SVG（anatomy kit）繪製；驗收包含「關掉 WebGL 仍可用」。

## 需求對照

| 需求 | SVG 能否滿足 | 說明 |
| --- | --- | --- |
| 真實行政界線與可核對圖釘 | 是 | GeoJSON → SVG path；座標在 WGS84，精度與來源寫在資料檔 |
| 縮放／平移／重設、鍵盤與觸控 | 是 | `camera.js`＋`view.js`；平面用 strict clamp，手機加 `insetBottom` |
| 等距插畫立體資訊圖感 | 是 | anatomy kit 底座、側壁、尺規、指北；明確標「立體示意視角」 |
| 列表／來源卡／時間軸同步 | 是 | 不依賴 3D 場景 |
| reduced-motion | 是 | CSS 與過渡可關；無強制相機動畫 |
| 無 WebGL／低效能裝置 | 是 | 本來就不載入 WebGL |
| 正式站 CSP `script-src 'self'` | 是 | 無 inline／無外部 3D runtime |

## 何時再評估 WebGL

只有在下列需求同時成立、且 SVG 已證明不足時，才值得評估：

1. 需要可自由旋轉的三維地形或真實建物高度，且讀者要拿來對照現地（不是示意沙盤）。
2. 圖徵密度大到 SVG DOM 互動明顯卡頓（粗估單場景可點擊圖徵上千、且要逐幀更新）。
3. 能提供靜態圖與「強制 2D」替代路徑，並通過同樣的載入失敗／無 JS／reduced-motion 驗收。

即使導入，也應：

- 立體層只作示意或明確標「模擬高度」，**不得**把建築高度畫成預算或政績分數；
- 真實位置仍以 2D／GeoJSON 為準；
- 預設走 SVG；WebGL 失敗或使用者關閉時自動退回。

## 現行替代

- 平面：正北、真實比例、比例尺。
- 立體示意：同一套地面座標的等距投影＋插畫家具；文字標示示意視角。
- 無 JS／資料失敗：`public/img/atlas/overview-*.svg` 靜態總覽與官方來源連結。
