# 地方治理追蹤：第一版與擴充方向

日常用途是回答「我關心的政策走到哪裡、證據在哪裡、還缺什麼」。選舉觀察保留為其中一個資料工作區。

## 已實作的首批試行

`/governance.html` 提供四地四案的地區與議題篩選、搜尋、瀏覽器關注清單、可展開證據紀錄、官方來源目錄與篩選結果 CSV。資料以人工查閱的官方文件為起點，查閱日是 2026-11-12，尚未自動刷新，未宣稱涵蓋各地全部政策。

台北培英公共住宅的 100% 工程進度保留原基準日，驗收、點交及入住分開追蹤。新北思源路人行天橋的 77.25% 未標示數字基準日，因此不能拿網頁更新日代替。新竹縣褒忠路保留核定經費與決標金額，實支及工程百分比未知。新竹市香山四號道路僅記載補辦土地公告，不推斷施工或啟用狀態。

這四案不是抽樣評分，不做跨地區排名，也不把媒體聲量、留言情緒當成治理成效。待補證據表示本站尚未收錄，不代表機關沒有公開。

## 資料結構

- Region：行政區與識別碼，可擴充全台。
- Project：政策或工程、主管機關、議題、階段紀錄。
- Event：日期精度、原文來源、機關聲明或公開文件的性質。
- Source：官方網址、來源更新日、本站查閱日；案卷引用與目錄入口分開。
- Progress：機關公布數字及數字基準日，未知保留 null。
- Budget：核定、決標與實支各自儲存，不自動互相推算。
- 後續擴充：Office / Term / Person（機關與任期關係）、Promise（承諾）、Outcome（可測量公共成果）、Correction（更正與版本）。人物與任期不綁死在個別選舉。

## 下一階段

1. 擴大台北、新北、新竹縣市的政策案卷；納入議會質詢、預算決算及驗收文件，逐案保留來源與時間。
2. 對可取得授權且穩定的官方資料新增排程匯入；內容變動進入待審紀錄，審核後更新案卷。來源失敗保留上次成功資料，不將缺漏覆寫成零。
3. 加入變更比較、責任機關與任期查詢，再依同一資料格式擴及全台。
4. 跨裝置關注與通知需另外實作登入、資料儲存及使用者明確設定；目前關注只在本機瀏覽器。

## 維護與部署

原始資料：`public/data/governance.json`、`governance-registry.json`。新版組裝器從已檢查的 editorial build 複製這兩份檔案，舊選舉資料匯入不覆寫治理案卷。發布器必須看見 `governanceBoard` 標記才接受新版。所有資料檔一併納入 manifest hash。

新增政策需要真實來源與可重現的摘要，不能建立假進度或示意預算。發布前跑資料測試、完整組裝與手機瀏覽器驗收。來源不足的欄位保留未知。
